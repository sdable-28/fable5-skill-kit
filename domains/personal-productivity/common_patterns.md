# Common Patterns — Personal Productivity & Executive Function

## 1. Weekly Review
**Trigger:** Fixed calendar slot (Friday PM or Sunday). Also fire ad hoc when open loops exceed working memory — missed commitments, "what am I forgetting" anxiety, stale task list.
**Approach:** 1. Empty every capture point to inbox zero-state: email, notes app, desk paper, browser tabs, chat saved-items. 2. Process each item: <2 min → do now; else clarify next physical action and file to project list, calendar, or waiting-for. 3. Scan calendar ±2 weeks: extract actions from past events, prep for upcoming. 4. Review every project for exactly one next action; a project with none is stalled — assign one. 5. Review waiting-for list; nudge anything older than its by-when. 6. Pick 3 MITs for next week and pre-block time for them.
**Checklist:** `[ ] All inboxes empty  [ ] Calendar back/forward scanned  [ ] Each project has a next action  [ ] Waiting-for chased  [ ] 3 MITs chosen  [ ] MIT blocks on calendar`
**Variation to watch:** Review degrades into list-grooming — reordering, retagging, tool-tweaking — with zero decisions made. If the review ends without new next actions or calendar blocks, it did not happen. Cap at 60 minutes.

## 2. Irreversible-Decision Workup
**Trigger:** A decision that is expensive to undo (quit/hire, large purchase, public commitment, architecture lock-in). Signal: you catch yourself deciding it the way you'd decide lunch.
**Approach:** 1. Classify first: reversible (two-way door) → decide in minutes at ~70% confidence and move; irreversible → continue. 2. Write a decision journal entry BEFORE deciding: the decision, options considered, expected outcome with probability, what would change your mind, emotional state. 3. Run a pre-mortem: "It is one year later and this failed — why?" List 5 concrete causes. 4. Invert: what guarantees failure? Eliminate those. 5. Check base rates: what happens to most people who make this choice, ignoring your specifics. 6. Name second-order effects: and then what? 7. Decide, set a dated review checkpoint, log it.
**Template:** `Decision: | Date: | Reversible? Y/N | Options: | Chosen + why: | Expected outcome (w/ %): | Kill criteria (what changes my mind): | Pre-mortem top 3 causes: | Review date:`
**Variation to watch:** Treating reversible decisions as irreversible — weeks of analysis on a two-way door. That is FOMO wearing a rigor costume. If undo cost < analysis cost already spent, decide today.

## 3. Deep Work Block Setup
**Trigger:** Any task requiring >45 min of sustained cognition (writing, design, analysis, hard debugging). Signal: task has been carried across 3+ daily lists without progress — it needs a block, not a slot on a list.
**Approach:** 1. Schedule 90–120 min against your energy peak, not whatever gap exists. 2. Define the exit criterion before starting: "done means X exists" — a shipped section, a working function, a sent doc. 3. Close email/chat, phone in another room, single monitor window, notifications off at the OS level. 4. Keep a distraction pad: intruding thoughts get one line on paper, not a browser tab. 5. Work the single task. On interruption, note the timestamp — each context switch costs ~23 min of recovery; count them. 6. End with a 2-line shutdown note: state reached, exact next step.
**Checklist:** `[ ] Exit criterion written  [ ] Notifications killed  [ ] Phone out of reach  [ ] Distraction pad ready  [ ] Shutdown note written`
**Variation to watch:** The block gets spent on "quick" shallow tasks to warm up. Warm-up is procrastination with a badge. First minute of the block = first minute on the named task.

## 4. Email / Inbox Triage Pass
**Trigger:** Scheduled 2–3× daily (never continuous). Also fire when inbox blocks others: someone is waiting on a reply gating their work.
**Approach:** 1. Timebox 20 min. 2. One pass, newest to oldest, touch each item once: delete/archive, reply if <2 min, delegate with an explicit by-when, or convert to a task with a next action and archive the mail. 3. Never leave an item "read but undecided" — that is a second future triage of the same item. 4. Replies use the briefing structure: context (1 line) → ask (1 line) → by-when (explicit date). 5. Unsubscribe or filter every recurring item you archived unread — fix the source, not the symptom.
**Template (outbound):** `Context: <1 sentence> / Ask: <specific action> / By: <date> / If no reply by then: <default action I will take>`
**Variation to watch:** Inbox zero becomes the goal. An empty inbox with untouched MITs is productivity theater — busyness mistaken for progress. Triage serves the day's priorities; it is never the day's achievement.

## 5. Meeting Audit & Async Conversion
**Trigger:** Quarterly, or when recurring meetings consume >30% of work hours, or when you leave a meeting having said nothing and learned nothing.
**Approach:** 1. List every recurring meeting: duration × frequency × your prep time = monthly cost in hours. 2. For each, name the decision or unblock it produced last cycle. None → cancel or decline the series. 3. Status-only meetings → convert to async written update (context → ask → by-when format, posted on a fixed cadence). 4. Meetings you must keep: demand an agenda and a decision owner; no agenda 24h prior → decline with the template. 5. Batch remaining meetings into 1–2 days to protect contiguous deep-work days.
**Template (decline):** `Skipping this one — no agenda posted / no decision needed from me. If something needs my input, send context + ask + by-when and I'll respond async within 24h.`
**Variation to watch:** Declining meetings but answering the async channel in real time all day — you converted one interruption format into a worse one. Async means batched replies on your triage schedule, not instant chat.

## 6. Cognitive Offload Sweep (Externalize Open Loops)
**Trigger:** Mental rehearsal of commitments ("don't forget to..."), waking at night with tasks, or the same reminder occupying attention twice in one day.
**Approach:** 1. Timebox 15 min. Brain-dump every open loop to one trusted list — commitments, ideas, worries, half-decisions. Do not filter or organize while dumping. 2. Clarify each: next action, or reference note, or explicit "decided: not doing" (write the no down — undedicated maybes leak back). 3. Route reference material into the notes system with a one-line progressive summary in your own words — a raw clipping is storage, not thinking. 4. Set reminders in the system with dates, never in memory. 5. Verify: the head is empty because the system is full.
**Checklist:** `[ ] Dump complete, nothing held back  [ ] Every item has next-action / reference / explicit-no  [ ] Date-bound items have dated reminders  [ ] Notes summarized in own words`
**Variation to watch:** Offloading to five systems (notes app + email-to-self + sticky notes + chat DMs + memory). Multiple partial systems = zero trusted systems, and the rehearsal loop returns. One capture inbox, ruthlessly.

## 7. AI Offload Decision
**Trigger:** A task feels delegable to an AI assistant, or you notice you've asked AI for something the third time this week (candidate for a standing workflow).
**Approach:** 1. Classify the task: verifiable output you can check faster than produce (draft, summary, transform, boilerplate) → offload; judgment where you are the check (final decisions, relationships, anything you must be able to defend unaided) → do yourself. 2. Prompt for maximum information density: give context, constraints, output format, and a concrete example — one dense prompt beats five clarification rounds. 3. Verify against your own criterion before using output; never forward unread. 4. If recurring, save the prompt as a template in your knowledge system. 5. Skill check monthly: redo one offloaded task manually — if you can no longer evaluate the AI's output, you've over-relied; pull it back.
**Template:** `Task: | Can I verify faster than produce? Y/N | Context given: | Output format: | My verification check: | Recurring? → saved prompt name:`
**Variation to watch:** Offloading the thinking instead of the typing — asking AI to make the decision, then rubber-stamping. The moment you can't explain why the output is right, you didn't delegate the task; you abandoned it.
