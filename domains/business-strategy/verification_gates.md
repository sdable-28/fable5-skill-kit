# Business Strategy — Verification Gates

Domain-specific pass/fail gates. Run before delivering any strategy analysis or recommendation.

### Gate 1 — Problem-Statement Precision
- **Pass:** The problem is stated as one falsifiable question with a decision attached ("Should we enter X, given Y?").
- **Fail:** The problem is a topic ("growth") or restates the client's symptom without a decision.
- **Check:** Read the problem line aloud — does answering it force a specific decision?

### Gate 2 — MECE Decomposition
- **Pass:** The issue tree's branches are mutually exclusive and collectively exhaust the problem; no item fits two branches, nothing material is unbranched.
- **Fail:** Branches overlap, or a driver of the answer is missing.
- **Check:** For each branch, confirm no sibling contains the same driver; sum-test the branches cover 100% of the problem.

### Gate 3 — Framework-Fit
- **Pass:** Each framework applied matches the actual question (Porter's for industry attractiveness, not for an operational cost problem).
- **Fail:** A framework is applied because it's familiar, not because it fits.
- **Check:** For each framework, state the question it answers and confirm it is this problem's question.

### Gate 4 — So-What Discipline
- **Pass:** Every exhibit, data point, and finding carries an explicit implication ("therefore...").
- **Fail:** A chart or number appears with no stated consequence.
- **Check:** Scan every data element — each has a "so what" sentence or it is cut.

### Gate 5 — Scenario Completeness
- **Pass:** At least 3 scenarios (base/optimistic/pessimistic), each with explicit named assumptions and a probability or trigger.
- **Fail:** A single point-forecast, or scenarios without stated assumptions.
- **Check:** Count scenarios; confirm each lists the assumptions that define it.

### Gate 6 — Unit-Economics Grounding
- **Pass:** LTV, CAC, payback, and contribution margin are computed stepwise from named inputs, not asserted.
- **Fail:** Round-number economics appear with no derivation.
- **Check:** Trace each figure to its inputs and re-derive one by hand.

### Gate 7 — Business-Case Sensitivity
- **Pass:** The DCF/business case includes sensitivity on the 2–3 assumptions that most move the answer, with a break-even for each.
- **Fail:** A single NPV/IRR with no sensitivity, hiding fragility.
- **Check:** Confirm a sensitivity table exists and identifies which assumption flips the recommendation.

### Gate 8 — Pyramid Structure
- **Pass:** The recommendation leads with the answer; the executive summary contains the full answer, not "see slide 3."
- **Fail:** The answer is buried after the analysis, or the summary points elsewhere.
- **Check:** Read only the first slide/paragraph — does it deliver the complete recommendation?

### Gate 9 — Implementation Path
- **Pass:** The recommendation includes sequenced actions, owners, and the organizational-change requirement.
- **Fail:** A recommendation with no path to execution ("they should reposition").
- **Check:** Confirm the deliverable answers "who does what, in what order, and what change-management it needs."

### Gate 10 — Analysis-Paralysis Guard
- **Pass:** The recommendation is made at the directionally-right threshold; further data collection is scoped only where it would change the decision.
- **Fail:** The deliverable defers the call pending perfect data that wouldn't change it.
- **Check:** Ask "would the missing data flip the recommendation?" — if no, the gate requires deciding now.
